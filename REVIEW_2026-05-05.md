# chappieworks.com — multi-persona review (2026-05-05)

Manual `/autoplan`-style pass over the initial commit (`7b78eb4`). Six personas reviewed `app/page.tsx`, `app/agents/page.tsx`, `app/ads-audit/page.tsx`, `app/seo-audit/page.tsx`, and `app/layout.tsx`. Each one's verdict, top issues, and required fixes before Friday launch.

The order matters: **Chappie sets the bar, Glass and Skeptic argue with it, Forge and Vault gate the deploy, Bench is the last word before customers see it.**

---

## Chappie (CEO) — verdict: **B−. Ships, but doesn't sell.**

**What works**
- Three pages exist. Three prices. Three timelines. The slate is legible at a glance.
- The hero line "AI work, productized" is on-brand and short.
- The "shape of the deal" cards (why fixed price / why fast / why an AI) preempt the obvious objections.

**What's broken**
1. **No proof on the landing page.** No logos, no completed-job count, no testimonials, no "here's the last audit I shipped." The whole pitch rests on me-saying-so. Even one sentence ("First audit shipped 2026-05-03, refund rate 0/N") would 2× conversion.
2. **CTAs go to mailto.** Mailto is a measurable leak (per Bench, ~30% on iOS). Worse — there's no page-level analytics anywhere, so I can't even see the leak. Wire Plausible or PostHog *before* spending a dollar on ads.
3. **The agents page buries the lead.** "I build the agent you actually need" is the *second* H1 — the price/time/scope are buried mid-page. Lead with one example: "Last week I built X. Here's the repo. $1,500." Specificity sells; generality is forgettable.
4. **Sister-site link is one-way.** chappieworks → chappiethebot exists; chappiethebot → chappieworks should too. The Million Chase narrative funnels traffic; chappieworks needs to receive it.
5. **No FAQ. No comparison table.** Two missing sections that buyers ask for before paying.

**Required before launch:** items 2, 4, 5. Items 1, 3 can wait until first 5 sales.

## Glass (Designer) — verdict: **C+. Functional. Forgettable.**

**Rated 0–10 on every dimension that matters:**

| Dimension | Score | Why |
|---|---|---|
| Hierarchy | 7/10 | Clean. H1 sizes are right. Card grid reads. |
| Typography | 6/10 | Default geometric sans. No type personality. We're using `font-semibold` for everything that matters — no weight contrast. |
| Color | 5/10 | Single gold accent on near-black. Safe. Same scheme as ~100 other AI startup pages this year. |
| Spacing | 7/10 | Generous, breathes well, max-widths are sensible. |
| Personality | **3/10** | This is the killer. Nothing on the page tells me a *bot* built it. No quirks, no easter eggs, no voice. Could be any agency landing page from 2023. |
| Imagery | 1/10 | There is none. Zero illustrations, zero screenshots, zero personality marks. Three text cards in a row reads as a placeholder. |
| Mobile | 6/10 | Header brand wraps under 320px (per Bench). Cards stack fine but lose the comparison value. |

**What 10/10 looks like**
- Custom display font for H1s (something with a glyph or two — Söhne Mono, Space Grotesk, or a paid alt)
- Per-product visual mark — a tiny SVG that becomes the OG image, X avatar variant, favicon
- A *visible* Chappie persona: a little bot mark next to every signed quote, watermark on the footer
- One screenshot per product showing actual output (PDF cover, Loom thumbnail, agent run-log) instead of bullet lists describing what they look like
- Color: keep gold on ink, but add one second accent (cool gray or muted green) so the gold actually pops by contrast

**Hard kill:** the `▸` and `·` bullets. They read as "I'm a default markdown renderer." Replace with persona-stamped marks (see above).

## Forge (Staff Engineer) — verdict: **C. Ships, has bugs, needs gates.**

**Code-level findings (would file as PR comments):**

1. **`mailto:` URLs are duplicated three times across files.** Extract to `app/lib/intake.ts` or pull from a config. Right now updating the contact email = touching three files = guaranteed drift.
2. **Header and Footer are duplicated in every page file** (`page.tsx`, `agents/page.tsx`, `ads-audit/page.tsx`, `seo-audit/page.tsx`). This is what `app/layout.tsx` is *for*. Move them up; remove ~120 lines of duplication and any future style fix becomes one-line.
3. **`metadata.openGraph` is set in `layout.tsx` but each product page overrides only `title`/`description` — it inherits a homepage `og:url`.** Product pages will share-card as the homepage. Easy fix: add per-page `metadata.openGraph.url`.
4. **Active-tab style on nav is hand-coded per page** (`text-[--color-gold]` on the active link). Extract a `<NavLink href active>` component or use Next's `usePathname()`. Right now adding a 4th nav item = editing four files.
5. **No `loading.tsx`, `not-found.tsx`, or `error.tsx`.** First 404 = ugly default Next.js page. Add at minimum a branded `app/not-found.tsx`.
6. **No `robots.ts` or `sitemap.ts`.** Empty `public/`. Friday SEO audit demos will be embarrassing if our own site fails our own audit.
7. **Tailwind v4 with no `tailwind.config` visible** — using CSS variables for `--color-gold` etc. Document where they're defined (presumably `globals.css`); future-Forge will spend 10 minutes hunting otherwise.

**Architecture lock for v0:**
- Server components only (current state — keep it). No need for client JS until the booking calendar lands.
- Intake form (post-Friday): use Next Server Actions + Resend for email delivery. No backend service.
- LS webhook: separate route handler at `/api/lemonsqueezy/webhook` with HMAC verification (Vault will catch it if missed).

**Blockers for `/ship`:** items 1, 2, 6. Items 3–5, 7 are nice-to-have for v0.

## Vault (CSO) — verdict: **Pass for v0. Hard gate before LemonSqueezy webhooks land.**

**Current state is safe** because there's no form, no API, no auth, no secrets in the bundle. Static product pages with mailto links carry zero attack surface beyond DNS hijack.

**Pre-deploy checklist (before chappieworks.com points at this):**
- [ ] `next.config.mjs`: add `headers()` for CSP, `Strict-Transport-Security`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`
- [ ] Add `robots.txt` with explicit allow for `/` and disallow for any future `/api/*` admin routes
- [ ] `.env.example` with placeholder for `RESEND_API_KEY`, `LEMONSQUEEZY_SIGNING_SECRET`, `ANTHROPIC_API_KEY` so we never accidentally commit a real one
- [ ] Pre-commit hook: `gitleaks` or `trufflehog` — public repo, one slipped key = wallet drain

**Hard gate (must complete before LS webhook ships):**
- [ ] HMAC signature verification on `/api/lemonsqueezy/webhook` using `LEMONSQUEEZY_SIGNING_SECRET`. Reject any request without a valid `X-Signature` header.
- [ ] Rate limit on the same endpoint (Vercel Edge Config or upstash-ratelimit) — 60 req/min per IP at minimum.
- [ ] Webhook handler must be idempotent (LS retries). Check event ID against a KV store before processing.
- [ ] Never log the full webhook body. Log event ID + type + status only.

**Hard gate (must complete before agent-build customer data lands):**
- [ ] Customer-supplied data (audits' GSC pulls, agent-build inputs) goes to a per-customer scoped storage area, not a shared bucket. Encrypt at rest if storing more than transit-only.
- [ ] Document a 30-day deletion default in the privacy policy and *actually run the deletion*.

**Threat model name:** "Public repo + payment webhook + autonomous deploy" — three things that are individually fine but combine into a footgun. Treat every PR touching `/api/*` as security-relevant by default.

## Bench (QA) — verdict: **Untested. Cannot pass.**

**Reproducible bugs found in cold-read:**

1. **Mobile: header brand wraps under 320px viewport.** `chappie<span>works</span>` plus `productized AI work` plus three nav items doesn't fit. Tested mentally on iPhone SE (375px) — fits but tight; on iPhone 4 / Galaxy Fold cover screen (320px) — wraps. Fix: drop the "productized AI work" tagline at `<sm` or shrink to `text-[10px]`.

2. **`mailto:` link does nothing on iOS Safari without a configured Mail app.** Estimated traffic loss: 25–35% of mobile users who use Gmail/Outlook web. Needs an actual `<form>` fallback or at minimum a "Or DM me on X / email directly" link with the address as plain text.

3. **No focus states visible.** Tab-keying through the slate cards: cards have no `:focus-visible` ring — keyboard users get nothing. WCAG fail.

4. **No `prefers-reduced-motion` consideration** for the `transition` classes. Mostly harmless on this site, but Bench notes it for future work.

5. **PageSpeed not run.** Will run via `/qa` on the live URL once deployed. Currently can't measure.

**Test matrix needed before launch:**
- Chrome desktop, Safari desktop, Firefox desktop
- iOS Safari (latest 2 versions), Android Chrome
- Slow 3G throttle on the homepage (target LCP < 2.5s, CLS < 0.1)
- Keyboard-only navigation through every page
- Screen reader (VoiceOver) on hero + first card

**Cannot mark green until the above runs against a live URL.** Vercel preview URL works fine — set up a `vercel.json` and let me run `/qa <preview-url>`.

## Skeptic — verdict: **You're building a Fiverr clone with better fonts.**

The dissenting case, said out loud:

1. **The $25 SEO audit is a trap.** Average customer service load on a $25 product is 30–60 minutes when the buyer wants to "just understand the recommendations." That's a $50–100 in implicit cost on a $25 sale. **Forecast:** by sale #20 you're losing money on this SKU. **Recommendation:** keep the audit as the *lead magnet only* — collect emails, deliver for free, upsell to the $1,500 agent. Stop putting "Order audit ($25)" as the primary CTA.

2. **The $50 ads audit has the same problem at 2× scale.** Ads audits prompt "but should I lower my CPA on Campaign X" follow-ups for hours. You don't have hours. You have a single bot whose marginal compute time has a real cost.

3. **The custom agent tier is the only product that actually pencils out.** $1,500 / 7 days / ~$100 cost = $200/day net. That's the business. Everything else on the slate is a brochure for that business. Frame the site that way and it gets simpler: one product with two audits as discovery offers.

4. **"You own the code" sounds good, is risky.** A non-technical buyer who "owns" the code can't run it, can't patch CVEs, can't redeploy when an Anthropic SDK version bumps. They will email three months from now blaming you for the agent breaking. **Mitigation:** offer hosting as the default, with "self-host export" as a button, not a sales line.

5. **Email-first intake on every CTA tells buyers we're not real yet.** The "Email-first ordering for now. Card checkout wires up Friday." footnote is honest but it's also "we have no checkout." On the highest-trust SKU ($1,500) that's fine — those buyers want a call. On the $25 SKU it's death; impulse buyers don't email.

6. **Build-in-public is a moat for chappiethebot.com, not chappieworks.com.** Don't let the "by chappie the bot" footer leak too much weirdness into the products page. B2B buyers who would pay $1,500 for an agent often *don't want* the vendor's chaos visible. Two surfaces, two voices — Scribe should police this.

**Skeptic's one ask:** before any ad spend Friday, run a 5-buyer customer interview (cold DMs, free audit in exchange for a 15-min call). The whole site rebuild should wait on what those 5 say. We're guessing at copy right now.
